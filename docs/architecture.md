# 구조와 결정

새 확장 프로그램을 만드는 structural 작업. 서버 없이 Manifest V3와 브라우저 기본 기능을 사용한다.

## 파일과 책임

- `extension/collector.js`: 현재 게시물의 JSON 데이터 → Instagram 웹 엔드포인트 → 부분 DOM 순서로 수집. 주입 함수이므로 모듈 외부 변수를 참조하지 않는다.
- `extension/media.js`: 허용 CDN URL 검사, 중복 제거, 파일 이름 생성.
- `extension/popup.*`: 미리보기와 선택, 수집 목록의 세션 캐시, 다운로드 상태.
- `extension/background.js`: 팝업에서 받은 요청을 검증하고 Chrome 다운로드로 전달. 항목별 실패 격리.
- `tests/`: 수집/다운로드 단위 테스트와 브라우저 UI용 모의 환경.
- `scripts/package.py`: 확장 파일만 담은 설치 ZIP 생성.

## 계획과 완료 기준

1. 수집: 사진/영상 혼합 캐러셀, 빠진 영상, API 오류와 잘못된 게시물 응답을 테스트한다.
2. 선택과 저장: 개별/선택/전체가 정확한 항목을 전달하고 실패한 항목 뒤에도 다운로드가 계속되는지 테스트한다.
3. 전달: 구문 검사, ZIP 내용 검사, 브라우저 UI 검증 뒤 설치 문서와 검증 한계를 공개한다.

## 왜 이 방식인가

상시 탭 감시와 전체 사이트 권한 대신 사용자가 누를 때만 `activeTab`으로 수집한다. 외부 다운로드 서버를 운영하거나 로그인 정보를 전달할 필요가 없다. 다운로드는 Chrome이 소유하므로 팝업이 닫혀도 이미 시작한 작업은 계속된다.

Instagram의 공식 플랫폼 API는 일반 사용자가 웹에서 여는 임의 게시물 저장 용도와 맞지 않아 사용하지 않는다. 웹에 이미 포함된 JSON을 우선 읽는다. 없는 경우 `/api/v1/media/{id}/info/`를 기존 로그인 상태로 요청한다. 이는 **비공식이며 실제 서비스 연동은 UNVERIFIED**다. `X-IG-App-ID: 936619743392459`는 알려진 웹 클라이언트 식별값으로, 비밀값이 아니며 현재 유효성은 UNVERIFIED다. 변경되면 수집기가 실패할 수 있다. 이 상수는 실측값처럼 제시하지 않는다.

API 실패 시 DOM을 읽지만 캐러셀 전체를 보장하지 않으므로 부분 목록 경고를 반드시 표시한다. 영상의 poster는 실제 영상으로 취급하지 않는다. 인증과 접근 제한을 우회하지 않는다.

12초 요청 제한과 요청당 100개 제한은 제품용 보수적 기본값이며 성능 측정으로 산출한 수치가 아니다. 재시도 루프는 없다. 전체 프로필 크롤링, DASH/HLS 결합, 스토리 지원은 범위 밖이다.

세션 캐시는 팝업이 닫힌 뒤 다음 캐러셀 장을 읽을 수 있도록 필요하다. 브라우저 세션 종료 시 사라지는 `storage.session`을 사용하고 `tabId` 및 게시물 경로로 구분한다. 영구 보관은 하지 않는다.

## v0.2.0 — 화면에서 바로 저장 (사용자 요청)

기존 activeTab 팝업 전용 설계를 바꾸어 Instagram에 한정한 정적 content script를 추가했다. `content-entry.js`는 `inline.js` 모듈을 isolated world로 로드한다. 모듈 파일만 Instagram 출처에 web-accessible로 선언하며 외부 실행 코드를 불러오지 않는다.

- `inline.js`: 게시물마다 Shadow DOM 버튼을 오버레이로 붙인다. Instagram의 flex/grid 레이아웃을 밀지 않으며 DOM 추가 시 중복 없이 새 게시물에 붙인다. 클릭할 때 수집 및 다운로드를 요청한다.
- `inline-media.js`: 화면과 스크롤/클리핑 조상에 보이는 면적을 계산하고 현재 사진 또는 영상을 고른다. API의 해상도별 후보 URL/영상 poster와 대조한다. 애매하면 첫 항목으로 대체하지 않는다.
- 수집기는 `postPath`와 `scopeId`로 피드의 해당 게시물만 대상으로 삼는다. `complete`가 참일 때만 화면의 전체 저장을 시작한다.
- 단일 저장은 네트워크 요청 전에 현재 항목을 스냅샷으로 고정한다. 요청 중 장을 넘겨도 클릭 당시 항목을 유지한다.

완료 기준: 두 번째 사진/세 번째 영상 개별 저장, 게시물 전체 요청, 동적 게시물 버튼 추가, 부분 데이터의 전체 저장 방지를 검증하고 설치본을 다시 로드한다. 이전 팝업 선택 저장은 유지한다.

## v0.2.1 — 최종 UI와 릴스 수정

사용자 최종 결정: 호버 없이 항상 표시. 일반 게시물은 즐겨찾기 왼쪽의 아이콘 두 개, 릴스는 좋아요 위의 아이콘 하나. 색상 박스·문자 라벨 없이 기존 Instagram 선형 버튼과 맞춘다. 이미지젠으로 만든 투명 PNG 2개를 사용한다([프롬프트](icon-prompts.md)).

릴스 오류 원인과 수정:
- 기존 경로 정규식은 `/reels/audio/…`를 게시물로 받아 `audio`의 숫자 ID를 조회하여 HTTP 400이 발생했다. 게시물 경로를 끝까지 일치시켜 오디오 탐색 링크를 제외한다.
- 릴스의 `<video>`는 `blob:`이고 poster가 없을 수 있다. 확인된 단일 영상 게시물은 해당 영상으로 대조한다. 불완전 캐러셀에 이 예외를 적용하지 않는다.
- 영상 뒤의 더 큰 흐린 배경 이미지를 현재 사진으로 잘못 고르는 경우를 재현했다. 면적이 비슷하고 겹치는 실제 video를 우선한다. 0.9 면적 기준은 DOM 선택용 보수적 휴리스틱이며 측정 최적값이 아니다.
- 페이지 전체 main 대신 영상과 좋아요 액션을 함께 가진 개별 릴스 컨테이너를 사용한다.

`caption`은 JSON 또는 미디어 응답의 게시물 본문에서 수집해 정규화·다운로드 메시지까지 전달한다. 파일명은 이모지·특수문자 제거 후 글자·숫자·공백만 남겨 앞 10개 grapheme + 원래 게시물 인덱스 두 자리. 원본 CDN 파일명은 사용하지 않는다. 이미지·영상 확장자를 구분하며 기본 다운로드 폴더에 바로 저장한다.
